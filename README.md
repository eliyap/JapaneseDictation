# 聴き取り — Japanese dictation practice

A listening drill: hear a sentence, type what you heard, grade it word-perfect.
Speed adapts to how you're doing, so you're always working just past the edge of
comfortable.

Static site. No build step, no server, no account. Deploys to GitHub Pages as-is
and keeps progress in `localStorage`.

## The exercise

- Audio plays at a per-sentence speed, starting at **80%** of natural.
- Type what you hear. **Enter** checks, **Space** replays, **Ctrl/Cmd+Space**
  replays while typing.
- Correct → **+5** points of speed. Wrong → **−10**.
- Speed stays inside **50–110%**.
- **5 correct in a row retires the sentence.** A miss resets the streak.

Grading is word-perfect after ignoring things you cannot hear — punctuation,
spacing, and full-width/half-width differences. Long vowel marks (`ー`) *are*
significant, but a sentence that differs only in those is flagged as a near miss
so you know what happened. Every judgement can be overridden; it's your ear, and
the app just holds the tally.

## Run it

```bash
npm run serve      # http://127.0.0.1:8765
```

Any static file server works. Opening `index.html` directly does not — the deck
is loaded with `fetch`, which needs `http://`.

## Add your own sentences

Edit `data/deck.json`. Only `id` and `text` are required.

```json
{ "id": "genki-12-04", "text": "宿題をしてから、寝ます。", "translation": "I'll sleep after doing my homework." }
```

Keep ids stable — progress is keyed by id, so you can add, reword, and reorder
sentences without losing your history.

## Generate the audio

Without audio files the app falls back to your OS's built-in Japanese voice,
which works immediately but sounds like a robot reading a form. For real
practice, pre-render the deck.

**VOICEVOX — free, local, no API key:**

```bash
docker run --rm -p 50021:50021 voicevox/voicevox_engine:cpu-ubuntu20.04-latest
npm run audio -- --provider voicevox --voice 3
```

**ElevenLabs — better prosody, roughly $2 for a 500-sentence deck:**

```bash
export ELEVENLABS_API_KEY=...
npm run audio -- --provider elevenlabs --voice <voice_id>
```

Then commit `audio/` and `data/audio-manifest.json` — that's what Pages serves.

Each sentence is rendered **once, at natural speed**. The 50–110% range is done
in the browser with `playbackRate` + `preservesPitch`, which time-stretches
without shifting pitch. One render covers every speed, so re-rendering per speed
step would be pure waste. Renders are content-addressed, so editing one sentence
re-renders one sentence.

```bash
npm run audio -- --provider voicevox --prune   # drop files no longer referenced
```

> Audio generated by VOICEVOX may be published with credit. The **voice models
> themselves may not be redistributed** — which is why this repo ships the audio
> and not the engine. Credit VOICEVOX and the specific character wherever you
> publish. See [docs/voicevox-wasm.md](docs/voicevox-wasm.md).

## Deploy to GitHub Pages

Settings → Pages → deploy from branch, root. There is nothing to build.

## Tests

```bash
npm test                      # scheduling + grading logic, no dependencies
npm run serve & npm run e2e   # browser: audio wiring, keyboard, persistence
```

## Why there's no TTS engine in the page

The obvious design is to ship a Japanese TTS engine compiled to WASM and
synthesise on demand. I costed that out against VOICEVOX properly — it needs
~160 MB resident (the Open JTalk dictionary alone unpacks to 103 MB), the voice
models can't legally be hosted on a public site, and it needs COOP/COEP headers
that GitHub Pages cannot send.

It's also unnecessary: runtime TTS was only ever needed to vary *speed*, and the
browser does that for free. Full write-up, with measurements:
**[docs/voicevox-wasm.md](docs/voicevox-wasm.md)**.

